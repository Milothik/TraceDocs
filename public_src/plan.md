# TraceDocs Jev evidence discovery

**How it works:** A question and a structured document go to Jev. A small document sends every block. A larger document sends a structural preview from every contiguous group to Jev; Jev chooses groups for full block judgment. A conventional search index cannot exclude evidence before this step. Every selected evidence object links to its document, section, position and page where available.

**Try it:** Open the prepared research case, choose a question, run the Jev evaluation and inspect its evidence set. Export the trace. The tenth question asks whether the paper demonstrates 99% Jev accuracy. The source does not evaluate Jev, so TraceDocs should abstain. The demo uses 12 prepared summaries of Liu et al., *Lost in the Middle*, TACL 2024: https://aclanthology.org/2024.tacl-1.9.pdf. These are summaries, not a verbatim paper or a benchmark.

**Answer and trace:** The app returns evidence to the calling LLM. It does not generate an answer itself. A supported answer should cite selected block IDs; the `verify_claim` WebMCP tool can check a proposed claim against a selected block. The exported trace includes block scores, structural decisions, selected evidence, coverage and optional claim checks. If no full block meets the visible illustrative thresholds, the status is `insufficient_evidence` with `answer: null`. If a section preview misses possible evidence or the call budget prevents complete full-block evaluation, the status is `evaluation_incomplete` with `answer: null`.

**Cost control:** Up to 24 blocks are judged directly. Larger inputs are grouped into up to 100 structural previews with at most 12 blocks each, then full blocks in Jev-selected groups are scored within a 120-call budget. The preview includes only the first 225 characters of each block. This may miss evidence; the trace exposes the coverage. Estimated cost is unavailable without pricing or billable units, and no measured savings are claimed.

**Daily limit:** Ten Jev evaluation requests per client IP per UTC day, shared across browser and HTTP MCP. The count resets at 00:00 UTC. Inspection does not consume the limit. A hashed IP and date are stored server-side. Users of one shared public IP share the limit; production proxy forwarding needs verification.

**Integration:** Browser WebMCP exposes document inspection, evaluation, evidence retrieval, trace retrieval and claim verification where `document.modelContext` is supported. The HTTP JSON-RPC endpoint is available at the application base path plus `/mcp`. Compatibility aliases preserve older tool names without restoring the previous three-block filter. External agent compatibility and a real Jev call must be tested with live credentials before claiming production readiness.
